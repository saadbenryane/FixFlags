# Decisions

*Durable decisions with rationale. Only product, soul, design, architecture, data, security, or quality decisions. Not trivial choices.*

| Date | Status | Decision | Context | Alternatives | Reason | Consequences |
|------|--------|----------|---------|-------------|--------|-------------|
| 2026-07 | Active | Passkey as the second factor for 2FA | Users asked for two-factor auth with passkeys; better-auth has no native passkey-as-2FA yet | TOTP-only 2FA; wait for better-auth 2.0 passkey-2FA | Passkeys are phishing-resistant and match the AI-builder audience (device biometrics / security keys) | Enable flow requires a registered passkey first. Backup codes cover recovery. OAuth sign-in is not gated by 2FA (better-auth default). |
| 2026-06 | Active | Inline worker as default deployment | Single-service setup is simplest for pre-revenue | Separate worker service | Default must work with zero config. Inline = one npm command. | Dedicated workers need `INLINE_WORKER=false`. Self-hosted scheduler replaces external cron. |
| 2026-06 | Active | Self-hosted scheduler replaces external cron | Avoid external cron dependency for stuck-audit recovery + nurture | Railway cron, Google Cloud Scheduler | Redis-lock guarded, runs inside worker. No external infra needed. | Defined in `lib/queue/recovery-scheduler.ts`. Cron HTTP endpoints remain for manual trigger. |
| 2026-06 | Active | Knowledge graph is internal-only; public reads through lib/graph/queries.ts | Prevent tight coupling between growth UI and internal graph schema | Direct graph_* table reads in public pages | Enforces MIN_SAMPLE_SIZE gate, decouples schema changes. | Public pages never import graph models directly. Queries layer is the API boundary. |
| 2026-06 | Active | AI two-phase: Triage (cheap, anonymous) → Prescription (post-signup, detailed) | Anonymous users get enough value to sign up; signed-up users get actionable fix prompts | Single-phase AI for all | Triage proves value. Prescription delivers the product. Different pageText limits per phase. | Triage: 2500 chars from fresh HTML. Prescription: 5000 chars from stored metadata. See `lib/audit/page-text-limits.ts`. |
| 2026-07 | Superseded | Feature freeze policy relaxed | Building a solid product requires shipping improvements, not just waiting for users | Focus on core loop quality + distribution | Scan depth, UI polish, security hardening all serve the core loop | |
| 2026-07 | Active | Three rubrics only: Message, Experience, Reach | Containment prevents scope creep; three is memorable | 5+ rubrics, single score | Simple mental model. Maps to how users think about their site. | No plans to add more rubrics. Each must earn its place. |
| 2026-07 | Active | Re-checks are free and unlimited | Core loop habit. User who re-checks sees value. | Gating re-checks by plan | Re-checks build the habit. Gating them destroys the loop. | Not a revenue lever. Never gate. |
| 2026-07 | Active | Marketing copy single source of truth: lib/marketing/copy.ts | Prevents copy drift across components | Copy in components, copy in CMS | Every component reads from one file. Tests enforce compliance. | Banned phrases tested. No hardcoded strings in components. |
| 2026-07 | Active | Brand name: FixFlags (not QualityOS) | Rebrand complete. Name is concrete, action-oriented. | QualityOS | "Flags" = unit of value. "Fix" = outcome. | Keep aligned: Flags not Findings. Rubrics not Areas. Re-check not Re-audit. |
| 2026-07 | Active | Edge middleware: cookie-presence only, no Prisma | Edge runtime cannot import Node modules | Server-side validation at edge | Cookie presence check is UX-only; server validates every protected route. | proxy.ts must stay Prisma-free. Matches both dev and prod cookie name variants. |
| 2026-07 | Active | OAuth provider availability resolved at runtime, not build time | Build-time gating hides buttons in production (creds not present at build) | Build-time env check | OAuth env vars are runtime-only on deployed service. | `useOAuthProviders` hook fetches `/api/auth/providers`. No rebuild needed to add OAuth. |
| 2026-07 | Active | Tech detection for prescription comes from performanceData.detectedTech, not htmlMetadata | htmlMetadata is optimized for triage (short text). Tech detection is richer in performanceData. | Using htmlMetadata | Performance data has structured tech detection, not truncated raw text. | `PrescriptionContext.techStack` → prompt. Separate from htmlMetadata flow. |
| 2026-07 | Active | MIN_SAMPLE_SIZE = 20 distinct sites before programmatic public pages | Prevents publishing data with insufficient statistical significance | Lower threshold (5, 10), no threshold | 20 is a reasonable minimum for benchmark data to be meaningful. | Enforced in `lib/graph/queries.ts`. Not configurable per-page. |
| 2026-07 | Active | eslint.config with a11y + import plugins | Catch accessibility and import issues at lint time | Base ESLint config | Prevention over manual review. | Part of `npm run lint` and CI. |
| 2026-07 | Active | Triage runs for all scans; prescription gated by includeAi + credits | Triage is the anonymous teaser (score, verdict, rubrics). includeAi only enqueues ai-review job. | Skipping triage for anonymous users | Product promise requires AI summary on every scan. | See `docs/audit-pipeline.md`. `triageAt` marks success; degraded path preserves flags. |
| 2026-07 | Active | Non-fatal R2 and AI key boot in production | Crash-looping on missing optional config freezes deploys | Fatal boot on missing R2/AI keys | Service stays up; /api/health reports degraded. Scans fail or degrade clearly. | `storageConfigured`, `aiConfigured` on /api/health. |
| 2026-07 | Active | Poll-time + scheduler dual recovery for stuck audits | Cron alone misses audits stuck between intervals | Cron-only recovery | Every status poll after 15s can requeue; scheduler catches long-stuck. | `recoverAuditJobOnPoll` + `runStuckAuditRecoverySweep`. |
