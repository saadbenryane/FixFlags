How We Reduced Our Bundle Size by 40%

Published on September 15, 2024 by Alex Chen. 8 min read.

The Problem

Our initial bundle was 2.4MB gzipped. Core Web Vitals were failing, and users on slower connections were bouncing. We needed to cut the bundle without rewriting the entire application.

We set a target: get the initial load under 1.5MB while keeping all existing features intact. Here's how we got there.

Step 1: Audit the Bundle

Before optimizing, we needed to know where the weight was. We used webpack-bundle-analyzer to visualize our dependency tree.

npx webpack-bundle-analyzer stats.json

The analysis revealed three major culprits:

  • Moment.js — 67KB gzipped, pulling in all locale files
  • Lodash — 52KB gzipped, full library imported for 4 functions
  • Chart.js — 62KB gzipped, loaded on every page

Step 2: Replace Heavy Dependencies

Moment.js was the easiest win. We replaced it with date-fns, which supports tree shaking. This single change saved 58KB.

// Before
import moment from 'moment';
moment(date).format('MMM D, YYYY');

// After
import { format } from 'date-fns';
format(date, 'MMM d, yyyy');

For Lodash, we imported individual functions: import debounce from 'lodash/debounce'. This cut it from 52KB to 3KB.

Step 3: Lazy Load Non-Critical Components

Chart.js was only used on the dashboard page, but it was bundled with the main entry point. We used dynamic imports to load it on demand:

const Chart = lazy(() => import('./Chart'));

This moved 62KB out of the initial bundle and into a separate chunk loaded only when users visit the dashboard.

Results

After these three steps, our bundle dropped from 2.4MB to 1.4MB gzipped — a 42% reduction. Core Web Vitals improved across the board:

  • LCP: 4.2s → 2.1s
  • FID: 180ms → 45ms
  • CLS: 0.15 → 0.02

What's Next

We're now looking at server-side rendering for the product pages and exploring edge functions for dynamic content. The bundle size journey never really ends — but getting the fundamentals right makes every future optimization easier.
