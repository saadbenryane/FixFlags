# The execution router must track evidence state

Date: 2026-10-06
Scope: canonical product coordination
Confidence: high

## Discovery

The roadmap and current implementation said the Outcome foundation and Safe
Signup were locally complete, while `knowledge/execution.md` still told agents
to begin Phase 1. `PRODUCT.md` also asserted a large dirty workspace after the
candidate had been integrated. Both were authoritative routing inputs, so the
drift could cause duplicate architecture work even though the detailed plan was
accurate elsewhere.

## Rule

A phase transition is incomplete until the short execution router and current
implementation baseline point to the next unproven evidence gate. Long plans
cannot compensate for a stale first instruction.

## Prevention encoded

- `knowledge/execution.md` now routes work to exact-SHA canary, client-matrix,
  Watch, and release evidence rather than Phase 1 construction.
- `PRODUCT.md` records the locally implemented Outcome patterns and the exact
  boundary between local verification and production proof.
- The masterplan's launch debt no longer describes Safe Signup or trigger
  convergence as unimplemented.
- Future reconciliation should search canonical sources for the prior phase's
  imperative and stale workspace-state claims whenever a milestone advances.
