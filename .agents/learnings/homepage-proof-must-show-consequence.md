# Homepage proof must show consequence

**Date:** 2026-09-14
**Area:** Homepage marketing and product proof
**Confidence:** HIGH
**Evidence:** Owner review, deterministic purchase fixtures, responsive browser review

## Pattern

A before-and-after example is weak when the customer-visible outcome barely changes. The previous contact example only added confirmation copy, so the product's business value had to be explained around the visual.

## Better contract

- Use one consequential behavior across the board, workflow, Flag packet, and notification examples.
- Make failure and recovery visibly different without relying on explanatory prose. The purchase example moves from an empty cart to one item and a reachable checkout.
- Segment check examples by Website, Store, and Web app for relevance, while saying explicitly that these are examples from one broad analysis rather than separate scan modes.
- Keep connections secondary. Name what is available now and mark planned context plainly.

## Regression prevention

Homepage tests reject the retired low-stakes and chore-heavy language, require distinct purchase evidence, verify the audience selector, and keep unsupported connections without active controls.
