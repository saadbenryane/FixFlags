# Public Outcome claims follow executable kinds

- **Date:** 2026-10-01
- **Scope:** Homepage acquisition copy and the executable Site Outcome contract.
- **Confidence:** High.
- **Evidence:** `watchableOutcomeKinds()` permits only `CHECKOUT` and `AVAILABILITY`, while the homepage coverage tabs advertised form submission, Signup, Login and generic core-action completion. A red regression reproduced the mismatch before the copy repair. The focused suite passed 17/17 afterward. The rendered Web app tab at 375×812 and 1280×900 showed the protected-flow boundary with no horizontal overflow or browser errors.
- **Discovery:** An audience-picker item is still a product promise. Calling unsupported behavior an example does not stop a prospective customer from reading it as shipped coverage.
- **Why it matters:** FixFlags earns trust by independently verifying behavior. Advertising an Outcome that confirmation deliberately refuses makes acquisition copy contradict the safety boundary and weakens the product's central claim.
- **Correct approach:** Build positive capability lists from behavior FixFlags can execute now. Put target Outcomes in vision and roadmap documents. When a protected flow is relevant to an audience, state the current limit plainly instead of presenting it as checked.
- **Prevention:** `CareHomepage.test.tsx` maps each confirmable Outcome name to the homepage capability list and requires claim presence to equal `watchableOutcomeKinds()`. The FixFlags marketing skill now routes future homepage edits through that contract.
